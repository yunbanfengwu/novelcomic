## 总原则（先定调，再动手）

1. **不造新引擎。** 全部能力在引擎 B（`agent_unit` / `autoflow`）上做；
   引擎 A（workflow.py DAG）的 branch 缺口不在本计划内补。
2. **跳步 = 强制重生成集合，不是真跳转。** 执行永远从链头串行走，
   缓存命中的节点秒过（缺才跑现状）；「从第 N 步进入」等价于
   「第 N 步及其下游受影响节点进 force 集合」。这样不用改执行模型，
   dry 排练、进度推送、防环全部照旧生效。
3. **提示词编辑框必须直连该节点执行时真实读取的那一层。**
   禁止在 unit config 再加一个"系统提示词"字段——那是第六份拷贝
   （五层现状见审计 §3.3），会加重不稳定而不是治好。
4. 老约束照旧：只在本地改不 push；不动 steps.py v1 语义；SQL 幂等；
   新第三方依赖进 requirements.txt；前端单文件 ≤200 行、跑 tsc/lint/build。

## 阶段 0 — 节点级强制重生成（force）【地基：质检回退与「重跑此步」都踩在它上】

**现状缺口**：强制重跑只有流程级全有全无（`only_missing:"no"`），
没有"这个节点无视缓存重跑、其余照常跳过"。两处直接受害：
① 质检回退重试时，上一节点（重装配/组合提示词）指纹缓存命中会秒回同样结果，
回退等于空转；② 运行画布「重跑此步」实测也是缓存命中秒回（7-30 实测
g.shot-elements"缓存命中秒回"），并没有真重跑。

**改动落点**：

| 文件 | 改什么 |
|---|---|
| `services/workflow_actions.py` | 5 个守卫工具（`shot.ensure_elements/ensure_sheets/ensure_blocking/reassemble_prompts/review_image_prompt`）各加可选 `force: bool` 参数，为真时绕过指纹/时效缓存。**默认 False，行为与现状完全一致** |
| `services/agent_unit.py` | `run_unit` 增参 `force: set[str]`（slug 集合，随递归/批量 sub_ctx 透传）；单对象缺才跑判断（`has_artifact` 那段）命中 force 则不跳；`_before` 调工具时本编排 slug 在 force 集合 → `args["force"]=True` |
| `api/agents.py` | `run-unit` / `autoflow` 请求体加可选 `force: string[]`，透传——「重跑此步」按钮带上自己的 slug 即变成真重跑 |

**验收**：
- dry 排练传 `force:["g.shot-sheets"]`，结果里该编排显示将真跑而非"产物已存在（缺才跑）"；
- 真跑镜 819（要素设定图全在）不带 force 全链零模型调用；带 force 只有指定节点重出；
- 「重跑此步」带 force 后不再缓存秒回；
- 不传 force 的所有既有调用行为不变（backend 全部测试过）。

## 阶段 2 — 质检本地回退（不合格 → 回退上一节点重生成，不从头来过）

**定稿语义（2026-07-31）**：
- 质检不合格**固定回退到上一个节点**（串行链中它前面那个 ref_flow，
  `g.shot-image-qc` 的上一节点即 `g.shot-reassemble`）重新生成，**不重入整条链**；
- 重试上限**配在质检节点自己身上**，默认**不合格重试 1 次**；
- 重试时把**上一次生成结果 + 质检不合格原因**传入上一节点，供其针对性重生成；
- 重试后重跑质检；次数用尽仍不过 → 停链标 `qc_blocked`，带完整评审意见返回。

**与现状内部小循环的关系**：`review_image_prompt` 内部已有一轮
"评审→自动重构→复审"，保持不动（v1 也在用，且是提示词层的廉价快修）。
外层回退**只在其最终结论仍为不合格时**触发——两层不叠加烧钱：
内部重构算工具自己的事，外层回退按质检节点配置计数。

**改动落点**：

| 文件 | 改什么 |
|---|---|
| `services/storyboard.py` `review_image_prompt` | 返回值补结构化字段：`passed: bool`、`reasons: str`（不合格的评审意见摘要）。落 meta 现状不变，v1 调用方不受影响 |
| `services/agent_unit.py` `_before` 串行分支 | 串行链执行到质检类节点（config 有 `qc_retry` 声明）且结果 `passed=False` 时：未达上限 → 用阶段 0 的 force 语义重跑**上一个 ref_flow**，ctx 附 `qc_feedback`（上次产物 + reasons），完毕后重跑质检节点（同样 force）；达上限 → 停链，结果标 `qc_blocked` |
| `services/workflow_actions.py` | 上一节点的工具（`shot.reassemble_prompts`，及配了 `task` 的 LLM 节点走 `agent_runtime`）接受可选 `qc_feedback` 参数：装配/生成时把"上次结果哪里不行"注入提示词上下文，做针对性重生成而非原样重跑 |
| `g.shot-image-qc` seed（幂等 UPDATE，新 SQL 文件） | 节点 config 加 `qc_retry: 1`（重试上限，画布可改；0=不回退，与现状同） |

**回退目标的确定**：固定取串行 `ref_flows` 里质检节点的**前一项**，
不做 LLM 判断、不做多级回退——与用户流程图"质检未通过 → 上一步"一致，
实现最简且可预测。以后要多级回退再重启阶段 1。

**验收**：
- 构造一镜提示词质检必不过（临时改 kb 评审规则拉高阈值），真跑观察：
  QC 不过 → `g.shot-reassemble` 带 `qc_feedback` 强制重跑（日志可见反馈注入）→
  QC 重跑 → 仍不过 → `qc_blocked` 停链，出图节点未入队；
- `qc_retry: 0` 或未配置时行为与现状完全一致（不回退）；
- 质检通过的镜零额外开销；dry 排练显示回退结构但不调模型。

## 阶段 3 — 节点提示词直连（编排/运行阶段点开节点编辑系统提示词）

**原则重申**：编辑的必须是该节点执行时真实读取的那份。按节点类型三条线：

### 3a. 守卫工具节点 → 直连 kb_entries（主线，样板已存在）

质检守卫已经是目标形态：`_reviewer_system(conn, project_id, "首帧提示词质检",
IMAGE_REVIEW_RULES)` 先查 kb（项目覆盖全局）、查不到回退代码常量。要做的是
把这条通道**接到其余守卫 + 暴露给画布**：

| 文件 | 改什么 |
|---|---|
| `services/workflow_actions.py` | `@register` 元信息加 `prompt_ref: {kind:'skill', agent_code, name} \| None`，声明每个工具执行时读哪条 kb。尚未接库的守卫（如 ensure_elements 里补建要素的 LLM 提示词）照 `_director_skill` 样式接上：**先库后常量，库里没有则行为与现状逐字一致** |
| `api/workflows.py` | `GET /{slug}` 的 `step_chain` 条目与 unit 工具节点带出 `prompt_ref` + 当前生效内容（含"生效层：项目覆盖/全局/代码默认"标注） |
| `api/tools.py` 或 kb 现有端点 | 保存入口：写 kb_entries 项目级条目（已有 kb CRUD 则复用，不新造） |
| 前端 `WfInspector` / `AgRunAligned` 节点面板 | 有 `prompt_ref` 的节点显示「系统提示词」折叠编辑框：显示当前生效内容与来源层，保存 = 写项目级 kb 条目；「恢复默认」= 删项目级条目回落 |

### 3b. step 节点（出图/装配类）→ 先纠错，再定向

- **短期（本阶段必做）**：编排画布上配了 `step` 的节点，`task` 编辑框
  置灰并提示"该节点提示词由装配链产出，编辑无效——请改『组合提示词』节点
  或下方词条"。现在填了被静默覆盖，是误导，先止血。
- **中期**：step 节点点开显示其装配真实读取的 kb 词条清单
  （质量词/负面词/景别/焦段等 `get_block` 键），逐条可跳转编辑——
  复用 3a 的同一编辑组件，数据来源是装配函数里的 `get_block` 调用清单
  （在 `production_canvas` 里为每个 step 声明一份 `prompt_blocks` 静态表）。

### 3c. task 真实生效的 LLM 节点 → 治理入仓（审计 P2-5，顺带做）

- 数据库里各编排的 `task`/`charter` 全量导出成幂等 seed SQL 纳入版本管理；
- `load_unit` **维持现状（草稿即时生效）+ 画布节点标"草稿生效中"**
  （2026-07-31 定稿，采纳推荐：画布迭代期改了立刻能试比版本闸更重要；
  等编排稳定进入多人协作再升级成只取 published）。

**验收**：
- 画布点开 `g.shot-image-qc`，看到当前评审规则全文与"全局默认"标注；
  改一句保存 → 项目级 kb 条目落库 → 重跑质检，日志可见新规则生效；
  恢复默认 → 回落代码常量；
- 未配置项目级条目的项目行为与现状完全一致；
- step 节点 task 框置灰提示可见。

## 镜 1098 真跑暴露的三个 bug（2026-07-31 五轮，已修）

用户截图：场景站位节点红字报错、后三个节点没跑、但「输出产物」已显示入队 #936。

1. **`shot.ensure_blocking` 必炸**：`ensure_scene_blocking` 返回的 `groups` 是**组数（int）**，

2. **子编排内部的工具失败被父节点绿字盖住**：父节点只显示「跑 N · 跳过 M」，
   里面炸了看不出来。新增 `agent_unit.tool_errors()`，父节点直接标红带错误原文。
3. **停链后仍然入队出图**：串联前置的任务失败/超时时，后续步骤只标 `skipped`，

**另一半是前端事件串味（截图里最迷惑的一点）**：#936 其实是子编排「单镜提示词装配」
