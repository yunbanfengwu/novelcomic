# 镜头生产画布 · 三阶段融合规范（before / run / next）

> 状态：设计基准（2026-07-26，据产品手绘示意图定稿）。
> 实现落点：`frontend/src/features/storyboard/ShotSopCanvas.tsx`、`frontend/src/lib/sopInstance.ts`、
> `frontend/src/components/InfiniteMediaCanvas.tsx`、后端 `GET /shots/{id}/production-canvas`。

## 1. 一句话定义

镜头的无限画布**就是一张 SOP 实例图**：整张画布被纵向分为 **before / run / next 三个大区**，
所有节点（过程环节、提示词、参考图、生成输出）都归属于某个区；
**空的环节以"待生成"节点直接可见，点击就地补齐**。不存在游离于三区之外的节点集群，
也不用长距离桥接线去"缝合"两块图。

## 2. 画布总体结构

```
┌───────── before ─────────┐┌──────────── run ────────────┐┌──── next ────┐
│ 获取基本信息              ││  ┌ 创意描述（提示词卡）      │ │              │
│   ↓                      ││  │                          │ │              │
│ 获取所需要场景 ──────────→││─→├ 项目场景画风锚点（参考卡）│ │              │
│   ↓                      ││  │                          ├→│ 图片/视频生成 │→ 保存 → 下游
│ 获取所需要角色 ──────────→││─→├ 阿砚 / 岚音（角色参考卡） │ │  （输出节点） │
│   ↓                      ││  │ 音频·×（声线参考卡）      │ │              │
│ 组合提示词 ──────────────→││─→└（供给 创意描述 的内容）   │ │              │
└──────────────────────────┘└─────────────────────────────┘└──────────────┘
```

- **before 区 = 获取/准备的过程环节**（纵向串行）：
  1. `获取基本信息`——镜头事实：原始剧本、分镜粗剧本、详细分镜、镜头内 Cuts、场景站位与连续性；
  2. `获取所需要场景`——本镜所需的场景/道具/空间类素材是否齐备；
  3. `获取所需要角色`——本镜所需的角色设定图与声线小样是否齐备；
  4. `组合提示词`——装配 + 质检本次目标（首帧/视频）的提示词。
  这些是**过程节点**（干活的环节，带状态与"重新生成"），不是素材本身。
- **run 区 = 本次生成工作区**：具体的**素材/编辑/执行节点**——
  创意描述（提示词编辑卡）、各参考图卡（场景锚点、角色卡、音频……）、生成输出节点。
  用户在这里改提示词、启停参考、点"立即生成"。
- **next 区 = 收尾**：生成结果的保存/回填（`keyframe_url` / `video_url` 落库、封面抽帧），
  以及"提供给下游"（首帧→视频生成；视频→连贯性检查/成片）。

## 3. 节点类型

| 类型 | 形态 | 归区 | 示例 |
|---|---|---|---|
| 过程节点（SOP 环节） | 小卡：状态图标 + 名称 + 摘要 + 重跑按钮 | before / next | 获取所需要场景、组合提示词、保存并回填 |
| 素材节点（输入卡） | 大卡：媒体缩略图 / 文本编辑区 | run | 创意描述、项目场景画风锚点、阿砚、音频·岚音 |
| 输出节点 | 大卡：产物预览 + 「立即生成」 | run（右缘，紧邻 next） | 图片生成 / 视频生成 |

状态四色（过程节点与输出节点通用）：
灰=空（虚线框，"待生成"占位）、蓝=在途（转圈）、绿=完成、红=异常（质检不合格 / 生成失败，摘要给原因）。

## 4. 连线语义（三种，视觉需区分）

| 边 | 方向 | 语义 | 样式 |
|---|---|---|---|
| 串行边 | before 区内部 上→下 | 过程先后依赖 | 实线 |
| 供给边 | before 环节 → run 素材卡 | 环节的产物落成工作区的具体卡片 | 点线箭头（示意图中的绿箭头） |
| 参考关联边 | run 素材卡 → 输出节点 | 本次生成引用哪些输入（可启停） | 现有紫色曲线 |
| 收尾边 | 输出节点 → next 环节 | 结果进入保存/下游 | 实线箭头 |

供给边按素材类别路由：
- `获取所需要场景` → 场景/道具/空间类参考卡（kind ∈ scene / scene_sheet / prop / storyboard）；
- `获取所需要角色` → 角色与音频参考卡（kind ∈ character / audio）；
- `组合提示词` → 创意描述卡（提示词编辑区的内容来源）。

## 5. 与后端运行实例的字段映射

数据源：`GET /api/projects/{pid}/shots/{sid}/production-canvas`（13 个固定节点）
+ 逐节点重跑 `POST .../production-canvas/nodes/{node_id}/run`。

| 画布节点 | 运行实例来源 | 判空/状态依据 |
|---|---|---|
| 获取基本信息 | `source_script` + `rough_storyboard` + `shot_detail` + `cuts` + `continuity` 聚合 | 任一子项为空→灰；全部就绪→绿 |
| 获取所需要场景 | `references` 中场景/道具类 | 有缺图项→红（列缺哪些）；齐备→绿 |
| 获取所需要角色 | `references` 中角色类 + `audio_precheck` | 同上 |
| 组合提示词 | `image_prompt`+`image_qc`（首帧目标）/ `video_prompt`+`video_qc`（视频目标） | 未装配→灰；质检不合格→红；通过→绿（显示得分） |
| 创意描述卡 | 提示词双字段（user + anchor 合并展示） | —（编辑区，保存走 `saveShotPrompt`） |
| 各参考卡 | `required_refs` / `reference_images` / `extra_refs` / 音频 speakers | 无图=虚线占位可点击去生成 |
| 输出节点 | `keyframe`（首帧目标）/ `video`（视频目标）+ `meta.gen` 在途态 | 灰/蓝/绿/红 |
| 保存并回填 | `persist` 语义：`keyframe_url` / `video_url` + 封面 | 有产物→绿 |
| 提供给下游 | 首帧→视频；视频→连贯性检查 | 上游完成→绿 |

重跑动作沿用既有语义：过程节点点击 = 调对应既有 API（`gen_prompts` / `gen_keyframe` /
`gen_video` / `audio_precheck`），与普通生成入口完全一致，画布不另造执行通道。

## 6. 布局规则

- **三区是虚拟分割，不是实体容器**：视觉上只有两条纵向细分割线 + 顶部区名
  （before / run / next），没有边框长条；节点不被"装进"任何盒子。
- **区内自适应网格，禁止无限竖排**：
  - 每个区按内容量自适应排布，目标是整图接近视口纵横比（一屏能看清骨架，平移只做微调）；
  - run 区参考卡按 **多列网格换行**（示意图中场景锚点与岚音并排、阿砚在下一行）：
    列数 = `ceil(sqrt(卡数))` 量级，卡多则先横向扩列、再纵向换行；
  - before 区过程节点纵向串行（数量固定为 4 个，天然不长）；next 区同理；
  - 区的横向宽度随内容伸缩（run 区最宽），分割线位置由各区实际内容宽度决定，不是等宽三段。
- 输出节点固定在 run 区右缘、纵向居中，紧邻 next 分割线，收尾边最短。
- 节点仍可自由拖动微调；布局只是初始编排，不锁死。
- 回落链：无运行实例时投影已发布产线 SOP（`gen_keyframe` / `gen_video`，见
  `backend/sql/28_shot_line_sops.sql`）；再无则退 8 环节链条。三种形态都遵守三区结构。

## 8. 分组大框（run 区）

参考素材**不各自对外连线**，而是按类别装进大框，**只有大框对外连线**（环节 → 大框 → 输出节点）：

- 框的数量**按镜头实际素材动态生成**，有哪类出哪个框：
  首尾帧 / 场景与空间参考 / 道具参考 / 故事板参考 / 其他参考（以上属「获取所需要场景」）、
  角色设定参考 / 声线参考（属「获取所需要角色」），外加「创意描述（本次提示词）」独立成框。
  空类别不出框。**同一前置环节的组必须相邻排布**，环节才能与其组整体对齐。
- **一环节一排**：同一前置环节的各组**横向并排在同一排**
  （场景+道具+首尾帧一排、角色+声线一排、创意描述一排）；排与排自上而下。
  框内卡片横向排开（超过 4 列才在框内换行）。
- **before 环节与该排垂直对齐**：环节 y = 其所连各组的整体垂直中心；
  next 的「保存并回填 / 提供给下游」对齐输出节点。
- **组是真实容器**：框内卡片是大框的 DOM 子元素（相对定位），拖框时**天然随动**，
  不靠 JS 同步坐标——这是"拖动时子节点飘走"的根治办法。框内任意空白处均可拖动整组；
  过程节点亦可自由拖动。拖动是会话内位移（叠加在编排坐标上），不入库。
- **卡片可脱离分组**：卡片拖到框外 → 自动脱离该组（转为世界坐标独立摆放，
  并恢复自己的对外连线，组计数 −1）；未拖出框 → 松手自动吸附回网格槽位。
  成员脱离后，剩余成员**依次前移填补空位**。
- **分组只属于主画布**：下钻子画布（点卡片图片打开的 tab）与主画布节点 id 同名，
  分组过滤必须按 `activeTab === 'main'` 生效，否则子画布节点会被误过滤掉。
- **端口画在大框上**：组内卡片不显示左右端口 dot，分组大框左右各一个 dot——
  连线以整组为单位，与"只有大框对外连线"一致。

## 9. 新增节点（双向拖线）

节点左右两个 dot 都能拖出连线，在空白处松手即创建新节点（选类型：文本/图片/视频/素材库）：

- **右侧 dot 拖出** → 新节点是**下游**（当前节点 → 新节点）；
- **左侧 dot 拖出** → 新节点是**上游**（新节点 → 当前节点）——
  这是给"视频生成/图片生成"这类输出节点补参考素材的入口（否则输出节点没有新增上游的办法）；
- 拖到另一个节点的 dot 上则直接连线，方向同样按起拖侧决定。

## 10. 非目标

- 画布不是第二套执行引擎：所有动作都转发既有 API / flow Step，状态永远从数据推导；
- 不持久化画布布局（节点拖动是会话内微调）；SOP 模板层的编排/布局持久化在
  系统管理的 SOP 编排画布（`visual_sops.spec.layout`）中完成。
