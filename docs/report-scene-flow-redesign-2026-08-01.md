# 报告一:单场景生成该怎么编排(2026-08-01)

> **已实施。** 定稿设计与实现记录见
> [tapflow-scene-flow-design-2026-08-01.md](tapflow-scene-flow-design-2026-08-01.md)；
> 本文保留为决策过程。下面第 ④ 条关于 OSS 的纠正、以及质检段的边界，均已落进实现。

## 结论:你的四节点方案是对的,比现在的 v5 干净

现在 v5 让用户在开始节点填「场景说明」,等于**把 LLM 该干的活塞给用户**。
场景说明是产物,不是入参。改成:

```
开始(项目/章/集 可空 + 场景)
 → 场景介绍(LLM,缺才跑)
 → 场景设定图(图片 LLM = 提示词装配 + 质检 + 出图,内置最小集)
 → next(转存 + 附件 + 建/关联要素)
```

## 四个节点的准确定义

**① 开始** —— 只要定位,不要内容
- `project_id` / `chapter_id` / `episode_id`:全部可空
- `scene`:`element_id`(从要素库点进来)或纯名字(新场景)
- 去掉参考图入参是对的:参考图不该手填。它有两个正当来源——要素已有的
  `extra_refs`(`element_refs` 唯一实现)、画布上游连进来的图片节点。

**② 场景介绍(LLM,缺才跑)**
- 判据:要素的 `brief` 空 → 跑;非空 → 跳过。
- ⚠️ **落地约束**:`agent_next.WRITE_TARGETS` 白名单只有
  `content_nodes.meta` / `content_elements.meta` / `content_elements.state` /
  `content_nodes.summary`,**没有 `content_elements.brief`**。要么加一条白名单,
  要么把介绍写进 `meta`。白名单是防「配置驱动写库」变成任意 UPDATE 的,别绕开它。

**③ 场景设定图(图片 LLM)** —— 三合一是对的
装配 + 质检 + 出图合成一个节点,画布上就是一张图片卡。理由:这三件事对用户是
**一件事**(「给我出这张图」),拆开只会让画布变成流程图而不是创作台。

- 关于「异步」:现在 `mode=async` 前端已经不阻塞(立返 run_id 后轮询)。
  但引擎内部是**串行等待**子任务——一次运行占一个 worker 槽。单场景没问题,
  批量几十个场景会堵。要真并发得改成「节点入队 + 工作流重入」,表结构不用动
  (`workflow_node_runs` 已按 `(run_id, node_key, iteration)` 记断点)。

**④ next**
- ⚠️ **纠正一处表述**:OSS 转存**已经在 `media.generate_image` 里做完了**,
  产物拿到手就是自家桶的永久链接。next 不需要「上传 OSS」,它只负责:
  挂附件(`content_attachments`)+ 回写落点 + 建/关联要素 + 通知。
- 现在这三件事由 `ElementSheetStep.next()` 做,是**唯一实现**。next 节点应该
  **声明落点**、由那个 Step 执行,不要在 next 节点里另写一份回写——
  同一份 meta 两个地方改,迟早写歪(`agent_next` 模块头就是这么写的)。

## 属性面板:图片 LLM 节点要加质检段

合并之后,「系统提示词」实际上是两份配置,面板要分开:

| 段 | 配的东西 | 复用什么 |
|---|---|---|
| 提示词 | 系统提示词(怎么写这张图)、技能、知识库、工具 | `agent_runtime.assemble` |
| **质检** | **质检提示词**、关联知识/技能、判据(阈值/维度)、重试次数、不合格回退到哪 | `agent_unit._qc_after` + `qc_retry` |
| 锚定 | 版式/画风/质量词(只读,来自绑定的最小集) | `element.layers` 的 anchor 段 |

质检这套**后端已经有了,不用新写**:
- `qc_retry`(默认 0=不回退)配在编排 config 里;
- 不合格 → **固定回退串行链的上一个节点**重生成,携带上一轮产物 + 问题清单
  (`_qc_feedback_text`),再重跑质检;次数用尽返回 `qc_blocked`,调用方停链、出图不入队;
- 反馈消费端:上一节点声明 `qc_feedback` 参数的工具留档,质检工具的 `prev_feedback`
  让重构针对性解决。

缺的只是**把质检提示词做成可配**(现在是 `review_image_prompt` 里的硬编码十维判据)。

## 关于「未来的独立质检节点」

同意现在用不上。画布上那个圆点质检节点的定位应该是**跨节点的批量抽检**
(一个节点检查多个产物),跟节点内置的自检不是一回事。内置自检是生成的一部分,
跨节点质检是验收的一部分。别把两者做成同一个东西。
