# Tapflow 工作流设计规范

本规范约束后续所有 Tapflow。工作流定义描述“怎么生产”，运行记录描述“本次生产了什么”，二者不得混写。

## 1. 三端资产同源

原弹窗参考面板、InfiniteMediaCanvas、Tapflow 使用同一统一引用记录和资产身份。任一端新增、删除或禁用参考后，另外两端重新读取必须得到相同数量和资产 ID。图片、视频、音频产物自动进入素材/附件库；文本作为节点产物和版本数据保存，只有明确声明为可复用知识或素材时才资产化。

节点保存覆盖正文、最终提示词、手编冻结标记、模型配置、引用节点 ID、技能/知识/工具/QC 配置和画布位置。重新打开不得只剩节点外壳。

## 2. 节点类型与职责

| 节点 | 用途 | 持久化重点 |
|---|---|---|
| start | 项目、章节、分镜等入口 | schema、默认值、上下文映射 |
| query/action/text | 查询或产出可复用文本 | step、正文、输出字段 |
| llm text | 独立可复用文本产品 | 约束、技能、知识、工具、引用、正文 |
| image/video/audio gen | 最终媒体生产单元 | 约束、技能、知识、工具、引用、QC、模型、比例 |
| subflow | 复用已发布流程 | slug、版本、输入映射 |
| loop | 对集合逐项执行 body | source、body、并发、失败策略 |
| qc | 结论需要复用或分支时独立存在 | 判据、阈值、结论 |
| link | 业务关联或落库 | action、target、映射 |
| next | 回写、附件、通知、后续流程 | writes、attach、notify、thenFlows |

内部取数、守卫、装配允许 `ui.hide`，前端桥接上下游边。只有可独立检查、编辑、复用或分支的真实产品才成为可见节点。

## 3. 生成节点所有权

最终媒体节点必须拥有“提示词生成约束”（不是最终提示词）、技能、知识库、工具、动态引用、参考筛选与上限、QC、模型和宽高比、最终提示词及手编冻结状态。最终提示词只显示在媒体节点下方炸开的生成条中。属于该媒体生产过程的提示词装配、质检和准备步骤不得拆成漂浮的可见节点。

业务工作流只声明宽高比（如 `16:9`），不得写死 `2560×1440`；像素尺寸由 provider adapter 按模型能力换算。

## 4. 引用、扇出与汇入

连线代表数据依赖及参考关系。`each` 把集合逐项送入循环，`collect` 表达集合值；媒体汇入时下游递归读取循环/subflow 的媒体产物。

一对多再对一的标准形态：关联要素分析 → 循环生成 N 张要素图片 → N 张图片全部直接连到最终关键帧节点。不得新增“汇聚节点”，图片本身就是下游参考。

分镜关键帧主画布只展示真实上游产品：关联要素分析、分镜脚本、要素图片循环、额外参考资产、最终关键帧、next。连续性、blocking、事实查询、sheet 保障等作为隐藏内部节点。

## 5. 循环节点的定义态与运行态

编排态只有一张循环模板卡：宽高与图片节点一致（默认 `460×273`），不显示实例列表。

循环图片模板采用单层视觉：外围标题使用图片 icon 表达产物类型；高亮循环 icon 作为独立浮动徽标悬在卡片右侧中部，横向一半位于卡片外、一半叠在卡片上。循环徽标不得接收鼠标事件；同位置出现的 `+` 输出端口必须覆盖在循环徽标上方并保持可点击、可拖线。中央采用纵向两行结构，第一行只显示图片 icon，第二行显示完整单行文字“获取核心要素图片”。内容层必须铺满卡片且背景透明，不允许出现浅色内层容器或嵌套第二层卡片。集合表达式与并发数只保留在悬停提示和属性配置中。

所有节点的左右连接端口必须使用独立的透明热区组件：热区永久渲染、背景透明，默认隐藏内部 `+`；只有指针进入该侧热区时才显示 `+`，不得再由整张节点的 hover 或 selected 状态触发。`+` 在热区内采用 absolute 定位并跟随指针，同时限制在热区边界内；热区空白不得触发节点拖动，实际 `+` 保留原有点击和拖线语义。

运行态只要选定了足以解析集合的上下文（例如分镜），预检就必须立即用 N 张独立图片节点组件替换母卡投影，不得等用户点击执行。已有设定图立即回显；缺图实例显示待生成。点击执行只负责补生成缺失产物并继续下游。每个实例有独立 ID、标题、状态、图片、错误和连线；全部直接连接最终下游节点。实例按 iteration 稳定排列，嵌套 subflow 输出递归提取实际媒体 URL。

运行实例是 transient projection：不得写入模板 graph、不得触发自动保存；新一轮运行、切回编排态或重置时清空。模板母卡和原始边始终保留在定义层。

运行投影仍必须支持节点在 X/Y 两个方向自由拖动，不得吸附回拓扑列。所有参数齐全且全部循环数量解析完成后，对完整投影图执行一次全量智能重排，随后永久关闭自动排版并交还自由拖动。真实生产对象首次进入时将该次布局保存为专属画布，后续打开不再自动重排；只有用户点击左下角、位于缩小和放大之前的“智能重排”按钮时才再次全量重排并保存。临时实例本身仍不得写进模板 graph。

重排触发信号是一次只读预检已经完整解析全部循环集合，而不是图片加载、生成完成或运行结束。循环实例使用标准 `460×460` 图片槽，在原循环节点的拓扑列内纵向展开；最终媒体节点仍位于右侧并接受全部实例引用。原图在槽内 `contain` 完整显示，因此排版只依赖 N，不猜测原图高度。用户一旦拖动运行实例，后续预检/轮询状态更新必须继承该实例的现有 X/Y，任何状态回填都不得将其复位到模板坐标。

列布局同时处理横向扩展和纵向堆叠：逐列统计循环，一列有一个循环就在其后插入一个实例列，有两个循环则插入两个实例列；同一循环的 N 个实例在自己的扩展列中纵向成组，实例组整体中心线与循环 owner 中心线对齐，后续普通拓扑列整体右移。编排模式显示列中心辅助线，节点可任意拖动但松手后仅 X 轴吸附到最近列，Y 轴不受限制；运行模式与真实生产模式不显示辅助线、不吸附坐标，允许完全自由拖动。

运行与真实生产模式在左下角控制栏提供参考线图标开关，位置紧邻“智能重排”按钮，默认关闭。开启后显示与编排态相同的列参考线，并同步启用松手后的 X 轴列吸附；关闭后参考线和吸附必须同时停用，恢复完全自由拖动。

运行与真实生产视图必须保留循环模板卡，不得用实例组替换或隐藏母卡。运行投影的可见链路为“上游 → 循环模板 → N 个实例 → 下游”；模板原本直达下游的边在投影视图中由实例到下游的边替代，但模板 graph 本身不修改。

媒体节点炸开的生成框必须限制在画布可视宽度内。参考区域采用“左侧自动参考操作固定 + 中间素材横向滚动 + 右侧新增/资产库操作固定”的结构；素材数量增加只能让中间区域滚动，不得撑宽生成框或越出画布。鼠标悬停生成框时滚轮事件不得冒泡成画布平移；悬停中间素材区时，普通纵向滚轮应转换为横向素材滚动。

## 6. 失败、版本与保存

required 元素失败时阻断最终生成；optional 元素失败可降级，但必须在实例卡和运行记录显示。每次模板结构或配置修改生成新版本；生产对象画布保存对象覆盖层，不能改写已发布模板。运行状态、实例卡和本次输出只进入运行记录/资产系统。

## 7. 禁止模式

- 循环母卡内部堆 N 行或 N 张缩略图；
- 把运行实例保存进模板图；
- 新增可见“汇聚节点”；
- 把属于最终媒体节点的提示词、质检、技能或准备步骤拆成漂浮节点；
- 把最终提示词误存到“提示词生成约束”；
- 在业务编排中写死 provider 像素尺寸；
- 只保存媒体 URL，不保存节点正文与生成配置；
- 三个资产入口各自维护副本或仅按 URL 猜测身份。

## 8. 端到端验收

1. 新建并编辑各类节点，关闭重开后正文、提示词、配置、引用和位置完整。
2. 三个资产入口的启用引用数量和资产身份一致。
3. InfiniteMediaCanvas 新增图片后 Tapflow 可见；Tapflow 新增后另外两端可见。
4. 编排态循环卡为图片规格、左上有循环 icon、内部无实例列表。
5. 选定分镜后、点击执行前即出现 N 张独立图片卡；真实运行后各自状态/图片/错误正确，并分别直连最终节点。
6. 运行前后模板 graph 一致，不含 `loopId::iteration` 节点。
7. 最终生成条显示装配提示词；属性面板显示约束、技能、知识、工具、引用和 QC。
8. 使用真实项目和分镜完成生成，保留运行记录、测试资产和截图，不删除测试数据。
9. 循环展开后节点仍可拖动，局部重排无节点遮挡；生成框不越界且中间参考素材可以横向滚动。
