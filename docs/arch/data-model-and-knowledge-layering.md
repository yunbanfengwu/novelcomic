## TL;DR

- **两条核心原则统摄全部设计**：①**1000 章不断不飘** = 项目基本信息 + 目录表逐章故事发展简介流水账 + 核心要素 + **要素出现章节索引**，整条故事线落地成数据，**每章生成前按需检索**这四路信息；②**专业** = 镜头语言/肢体动作/运镜等专业提示词沉在知识库，生成时**动态按需获取**，不靠模型即兴。

- **知识分两层**：公共知识（镜头/动作/视觉风格，全局作用域）+ 项目级知识（小说资料/参考资料，项目作用域）；静态靠绑定、变化靠召回。
- **项目记忆表**承载"项目级用户偏好"（如"写作员工用莫言的语言写"），作用域模型参考 mem0（user×project×agent）+ mneme rules 级联设计（窄覆盖宽）。

## 〇、两条核心原则（用户 2026-07-08 定稿）

### 原则 1：1000 章不断、不飘 —— 故事线全部落地成数据，逐章按需检索

**病灶**：长篇飘掉的根因是"故事状态只活在模型上下文里"——上下文装不下 1000 章，靠模型记忆必飘。**解法 = 把故事线落成四路结构化数据，每章生成前确定性检索注入**：

| 检索路 | 落点 | 内容 |
|---|---|---|
| ① 项目基本信息 | 基本信息表 | 世界观基调/题材/主线一句话/卷级大纲轻引用 |
| ② 章节流水账 | **目录表逐章记录「故事发展简介流水账」** | 每章写完即回写本章简介（谁做了什么、局势变化、抛出/回收了什么伏笔）；生成第 N 章时取「最近 K 章流水账 + 卷级摘要」双粒度 |
| ③ 核心要素 | 核心要素表 | 人物卡（当前状态/目标/关系）、场景卡、设定卡——**要素状态随章节推进而更新**，不是静态设定 |
| ④ 要素出现索引 | **核心要素 × 出现章节** 关联索引 | 本章涉及哪些人物/场景/伏笔 → 反查它们上次出现在哪几章、当时状态如何，精确召回相关章节流水账而非全量 |

**生成第 N 章的检索管线（确定性，不靠模型自觉）**：
```
大纲定位(本章该发生什么) → ④查本章要素上次出现章 → ②取相关章+最近K章流水账
→ ③取要素当前状态卡 → 装配进写作员工上下文 → 生成 → 回写:本章流水账+要素状态更新+出现索引
```
**写后回写与写前检索同等重要**——回写不做，检索无源。此设计与调研互证：ainovel-cli 四维检索（伏笔/人物出场/状态变化/关系）、AI_NovelGenerator 状态跟踪、mneme 多层摘要，见 [../research/novel-writing-survey.md](../research/novel-writing-survey.md)。

### 原则 2：专业 —— 画风/视频用专业知识，动态按需获取

**病灶**：让模型即兴写"镜头怎么拍、人物什么动作"出来的是业余描述。**解法 = 专业提示词是知识资产**：镜头语言（景别/角度/运镜）、肢体动作（打斗/情绪/日常）、视觉风格（画风/调色/质量词/负面词）全部沉淀为知识库里的**结构化专业提示词块**，生成分镜/出图/出视频时**按本镜内容动态召回**（这一镜是打斗 → 召回武打动作块 + 快速运镜块），装配成最终提示词——**prompt 是编译产物不是字面量**，专业度来自知识库而非模型发挥。

## 一、六大核心表

| # | 表（中文定义） | mneme 对应 | 装什么 |
|---|---|---|---|
| 1 | 基本信息 | `content_projects` | 项目一行；`project_type` 区分种类；config JSONB 放**轻引用**（画风 id/主角色 code）——专业提示词不进基本信息，防膨胀。检索路① |
| 2 | 目录 | `content_nodes` | 卷/章/分镜的树形目录；**每个章节点带「故事发展简介流水账」字段**（本章写完即回写：情节推进/局势变化/伏笔抛收），是检索路②的数据源；卷节点带卷级摘要（双粒度） |
| 3 | 正文 | `content_bodies` | 章节正文、分镜脚本；一章=一条 body（章节是 body 级不是子项目级，mneme 物料/产出分层结论） |
| 4 | 核心要素 | `content_elements` | 角色卡/场景卡/世界观设定（character/scene/idea）；**要素状态随章节推进更新**（人物当前处境/目标/关系），非静态设定。检索路③ |
| 5 | 附件 | `content_attachments` | 生成的图/视频/音频产物回挂（媒体引擎异步作业完成后回写落点） |
| 6 | 任务队列 | `task_queue`(task_runs) | 生图/生视频长任务：pending→progress→done/failed，产物回写协议 |

**核心要素出现索引（原则 1 检索路④，六表之外的关键关联）**：`要素 × 章节` 出现关系（element_id, node_id, 本章内该要素的状态快照/事件摘要）。落法待拍板：独立关联表（推荐，可带状态快照与索引）vs elements 表 JSONB 数组（轻但难查询）。它是"精确召回相关章节而非全量"的支点。

## 三、知识两层

```
公共知识（全局作用域，全项目共享）= 原则 2 的"专业提示词资产"
 ├─ 镜头语言（景别/角度/构图/运镜——推拉摇移跟升降，专业术语级提示词）
 ├─ 肢体动作（打斗/情绪/日常——变化最大，情境召回的典型）
 └─ 视觉风格（画风/调色/质量词/负面词，拆正交轴成可组合块）

项目级知识（项目作用域，随项目走）
 ├─ 小说资料（原著文本/设定集）
 ├─ 参考资料（用户上传）
 └─ 角色一致性（内容轴单列，非风格轴：角色卡+参考图+LoRA 引用）
```

**召回策略（沿用 mneme 三层召回结论）**：项目固定块直接带（画风轻引用）→ 情境块按内容召回（这一镜有打斗→召回动作块）→ 通用块兜底。**静态靠绑定、变化靠召回**。每块结构化（正/负词 + LoRA/底模 + 参数），不打包成大文档。

## 四、与数字员工的关系

- 数字员工**属于项目**（新建项目自动 seed 一套：写作/绘画/导演/配音…，每项目独立可改）。
- 员工挂技能（how）+ 知识（what）；生成时装配器按「员工 charter + 技能召回 + 两层知识召回 + 项目记忆级联」编译出最终提示词——**prompt 是编译产物不是字面量**。
- 用户偏好入口：对话中说"以后写作用莫言的语言"→ 落项目记忆表一条 soft 偏好（scope=project+写作员工）→ 后续每次装配自动注入。
